# FMCG ERP/MES demo — local scope

User confirmed one FMCG company, three plants (beverages, packaged food, personal care), 1,000 workers per plant, and accounting target Circular 99/2025/TT-BTC. Demo only; no real personal data. Carbon is an independent app; CC1 Odoo schema gate is N/A.

Implement through existing company reference bootstrap and all twelve dataset tiers, with a new data-only FMCG dataset and additive company-scoped workforce/plant expansion. Preserve existing companies and database; no reset or constraint bypass. Use the existing local administrator identity, normal company membership and supported default permissions; synthetic workers are non-login records without auth accounts or administrator permissions.

Acceptance:

- Three manufacturing locations plus a separate headquarters; exactly 3,000 active synthetic workers, 1,000 per manufacturing location, with shifts/jobs and no authentic personal identifiers.
- Coherent FMCG items, materials, BOM/routings, orders, purchase/receipt, stock/lot trace, production/jobs/operations and MES execution data.
- ERP/MES module coverage checked against current schema and actual company rows, including explicit justified exclusions for inapplicable product CAD and external integrations.
- VND accounting, company-group-scoped Vietnamese account mapping, source-linked journals and debit-credit equality. Explicit legal/capability mapping for TT99; no assertion of complete compliance without statutory reports, disclosures and transition controls.
- Atomic seed transaction; dry-run rolls back; repeat command verifies existing company instead of wiping it. Read-only verification records counts, balances and cross-location links. Run dataset validation, scoped source checks and localhost HTTP checks.

Method: existing cc1-agentic-build binding, BMad implementation and TEA verification adapted to dataset work. No production deployment. Existing personal-fork push remains subject to its incomplete earlier ERP typecheck gate.
